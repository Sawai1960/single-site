# シングルサイト解析のための HGVS–GRCh38 座標自動変換ツール

HGVS 表記（c.・p.・g.・m.）および遺伝子名で記載されたバリアントを、NCBI RefSeq 転写産物のゲノムアライメントに基づいて GRCh38（hg38）のゲノム座標に変換し、検査依頼書用の 9 桁表記を出力します。がん・難病のシングルサイト解析（家系内解析を含む）における対象座標の特定を支援します。

> **本ツールは、HGVS 表記の変異を hg38 のゲノム座標に換算し、検査依頼書への記入を支援するものです。診断や治療方針の判断を行うものではありません。臨床遺伝専門医・認定遺伝カウンセラーなど、遺伝学的検査の依頼に携わる方の利用を想定しています。ご使用の前に、末尾の「[利用上の注意と免責事項](#利用上の注意と免責事項)」をご確認ください。**

シングルサイト解析（既知の変異 1 か所だけを調べる検査）の依頼書に記入する **hg38 のゲノム位置**を求めるための Web ツールです。
がん関連の遺伝学的検査で見つかった変異に加え、難病の遺伝子パネル検査で見つかった変異を家系内で確認する（家系解析）場合にも使えます。
次の 4 形式の位置情報を入力すると、hg38 上の位置と依頼書用の **9 桁ゼロ埋め表記**を出力します。

変換の前に、かずさ遺伝子検査室の依頼の区分を選びます。区分によって依頼書用の表示と注意が変わります（変換の計算は同じです）。

区分と注意は、公開されているかずさ遺伝子検査室の検査案内書（K110-40 Ver 8、K110-6 Ver 9）をもとに作成したものです。本ツールはかずさ遺伝子検査室が公式に承認したツールではなく、同検査室（公益財団法人かずさ DNA 研究所）とは関係ありません。

| 区分 | 検査（検査案内書） | 依頼書用の表示 | 区分ごとの注意 |
| --- | --- | --- | --- |
| がん関連遺伝子（対象 60 遺伝子。画面で一覧を表示できます） | がん関連遺伝子のシングルサイト解析（K110-40 Ver 8、NGS） | 遺伝子名＋9 桁の位置 | 60 遺伝子以外、UTR、イントロン側 10 塩基より深い位置、10 塩基を超える欠失・挿入 |
| それ以外（Sanger 単一エクソン） | ヒト遺伝子単一エクソン受託解析（K110-6 Ver 9） | `CYBB chrX:37783542 NM_000397.4 c.194T>G` の 1 行（Sanger 検査依頼書 2023 v1.2 の記載例の形）と 9 桁（参考） | 60 遺伝子に含まれる遺伝子、欠失・挿入、自動で入らない項目（c. 表記の変化など）、1 依頼 5 か所まで |

| 形式 | 内容 | 入力例 |
| --- | --- | --- |
| 1 | リファレンスゲノムバージョンとゲノム位置（ミトコンドリア DNA の m. 表記を含む） | `hg38, chr1:195507262` / `hg19 chr7:55259515 T>G` / `NC_000004.12:g.55113391C>T` / `NC_012920.1:m.3243A>G` |
| 2 | スプライシング型指定のコーディング DNA 位置 | `NM_002253.2:c.889G>A` / `NM_002253.2, c.889G>A` / `NM_000546.6:c.375+1G>A` |
| 3 | スプライシング型指定のタンパク質アミノ酸位置 | `NP_443086.1:p.Asp509Glyfs` / `NP_004976.2:p.G12D` |
| 4 | スプライシング型不明（遺伝子名 + c. / p.） | `KDR:c.889G>A` / `EGFR p.Leu858Arg` |

## 主な機能

- **c. → ゲノム**: エクソン、イントロン（`c.375+1`）、5'UTR（`c.-30`）、3'UTR（`c.*10`）、範囲指定（`c.68_69delAG`）に対応します。
- **p. → ゲノム**: 指定したアミノ酸のコドン 3 塩基のゲノム範囲を出力します。ミスセンス・ナンセンス変異の場合は、そのアミノ酸変化を起こす **1 塩基置換の候補**（c. 表記と hg38 位置）を一覧表示します。
- **リファレンス照合**: 入力した参照塩基やアミノ酸が hg38 と一致するかを確認します。不一致の候補は末尾に分けて表示します。
- **旧バージョンの NM 番号**: `NM_002253.2` のような旧版も、UCSC の RefSeq Historical アライメントを使って変換します。
- **UCSC に無いバージョン**: UCSC がアライメントしていない NM_/NP_ のバージョン（UCSC より新しい版も含む）は、NCBI からその版の配列を取得します。UCSC にある別の版と配列を照合し、両者で配列が同じ部分だけ位置を求めます。配列が違う部分や、その境界から 10 塩基以内は、推測せずにエラーにします。
- **バージョン番号なしの NM_/NP_**: `NM_004333:c.100G>A` のようにバージョンが無い場合は、全バージョンで計算して位置を比べます（FoundationOne の報告書など、NM 番号にバージョンが書かれていないことがあるため）。UCSC のデータに無い途中の版は NCBI の配列で補います。すべて同じ位置なら「変換成功」、版によって位置が違えば「要確認」とし、版ごとの位置を表で示します。
- **外部データベースとの照合**: 各候補について、UCSC のアライメントを使わない NCBI Variation Services と Ensembl VEP（RefSeq 転写産物）で同じ変換を行い、本ツールの結果と並べて「一致／不一致／確認不可」を示します。c. → hg38（順変換）と hg38 → c.（逆変換）の両方向を照合します。不一致の候補があれば結果を「要確認」にします。
- **スプライシング型不明（形式 4）**: 遺伝子の全転写産物で計算し、MANE Select を先頭に表示します。ゲノム位置が転写産物によって何通りに分かれるかも示します。遺伝子の別名（例: `VEGFR2` → `KDR`）にも対応します。
- **形式 1 の確認**: hg38 の参照塩基と、その位置に重なる転写産物の c. 表記を表示します。hg19 の位置は Ensembl の assembly mapping で hg38 に変換します。
- **ミトコンドリア DNA**: `m.3243A>G`、`NC_012920.1:m.3243A>G`、`MT-TL1:m.3243A>G` のような m. 表記に対応します。m. の番号は rCRS（NC_012920.1）の座標で、hg38 の chrM と同じです。位置にある遺伝子（MT-TL1 など）と種類（tRNA・rRNA・タンパク質をコードする遺伝子・D-loop）を表示し、遺伝子名を一緒に入力した場合は位置と合っているか確認します。変異の割合（ヘテロプラスミー率）と、核 DNA にある似た配列（NUMT）について注意を出します。hg19 の chrM は、UCSC では rCRS と番号が違う配列（NC_001807）のため注意を出します。
- **依頼書向けの注意表示**: 欠失の範囲指定、相同領域のある遺伝子（PMS2・BMPR1A・SDHD・CHEK2・NF1・SDHA）、シグナル配列の番号表記について注意を表示します。区分ごとの注意は上の表のとおりです。がん関連遺伝子を選んだ場合、ゲノム位置の入力で複数の遺伝子が重なるときは 60 遺伝子の候補を先頭に表示します。
- **欠失・重複・挿入の位置**: 同じ配列の繰り返しの中にある場合は、HGVS の g. 表記の規則どおり +鎖の 3' 側に寄せた位置を示します（Sanger 依頼書の「HGVS 命名法に従ったゲノムポジション」）。c. 表記は転写産物の向きで 3' 側に寄せるため、− 鎖の遺伝子では c. の番号から直接換算した位置と数塩基ずれます。その場合は両方の位置を表示します。
- **複数コピーの遺伝子**: コード領域の半分以上が、配列が 95% 以上同一の重複領域（UCSC `genomicSuperDups`）にある遺伝子（GAGE、GSTT2、SMN1、CYP2D6、OPN1LW など約 1,000 遺伝子）では、もう一方のコピーの位置と遺伝子名を示して注意を出します。データベースによって対応付けるコピーが違うことがあり、塩基の照合では区別できないためです。
- **転写産物と hg38 の挿入・欠失の差**: 位置の近くで転写産物と hg38 に挿入・欠失の差がある場合は、反復配列の中で位置がずれうることを注意します。
- **遠い上流・下流**: `c.-N` / `c.*N` が転写産物の外にある場合は、100 kb までゲノム上で延長して計算します（DMD の上流プロモーターなど）。
- **出力**: 9 桁表記・遺伝子名・Sanger 依頼書用の 1 行のコピー、UCSC Genome Browser（hg38、該当位置をハイライト）へのリンク、CSV ダウンロード（Excel で開ける UTF-8 BOM 付き。依頼書用表記と区分チェックの列を含む）。

## 起動方法

Node.js 20 以上が必要です。

```bash
npm install
npm run dev
```

ブラウザで <http://localhost:43127/single-site/> を開きます。

初回の `npm run dev` で、転写産物データの元データを UCSC と NCBI からダウンロードし、`public/data/` に目次（`index.json.gz`、約 1.5 MB）と遺伝子ごとの束（`b/0000.json.gz`〜`b/1023.json.gz`、合計約 12 MB）を作ります。2 回目以降はそのデータを使います。データの形式が古い場合は自動で作り直します。最新データに更新するときは次を実行します。

```bash
npm run data
```

## 公開（UMIN SQUARE）

本ツールはサーバーを使わず、ブラウザだけで動きます。`npm run build` で `out/` に書き出したファイルを、UMIN SQUARE（<https://square.umin.ac.jp/single-site/>）の `html/` に置いて公開します。

データの更新、書き出し、UMIN への送信は、次の 1 行で行えます（Windows の PowerShell では `npm.cmd`）。途中で UMIN のパスワードを入力します。

```bash
npm run publish
```

- `npm run publish -- --skip-data`: データを取り直さずに書き出して送信します。
- `npm run publish -- --no-upload`: 書き出しだけ行います。`npm run preview` を実行すると、<http://localhost:43128/single-site/> で UMIN と同じ住所の形で確認できます。
- 送信先は `UMIN_USER`（既定 `single-site`）、`UMIN_HOST`（既定 `square.umin.ac.jp`）、`UMIN_DIR`（既定 `html`）で変えられます。公開する住所を変えるときは、`BASE_PATH`（既定 `/single-site`）も合わせて変えます。
- 送信には Windows 標準の `sftp` を使います。うまくいかない場合は、WinSCP などで `out/` の中身を `html/` に送ってください。
- 公開する住所は `https://square.umin.ac.jp/single-site/` にしてください。バーチャルホスト（`single-site.umin.jp`）や `~single-site` の住所では、画面の部品が読み込めません。

半年に 1 回程度の更新で十分です。手元のデータに無い新しい版の NM_ も、NCBI の配列を使って換算できるためです。

## 仕組み

- **転写産物の構造**: UCSC hg38 の `ncbiRefSeqPsl` / `ncbiRefSeqPslHistorical`（RefSeq 転写産物のゲノムへのアライメント）、`ncbiRefSeqCds`（CDS 範囲）、`ncbiRefSeqLink`（遺伝子名と NP 番号）を使います。アライメントのブロック単位で座標を計算するため、転写産物とゲノムの間に小さな差異があっても正しく対応付けられます。
- **MANE**: NCBI の MANE summary（GRCh38）を使います。
- **重複領域**: UCSC の `genomicSuperDups`（分節重複、95% 以上同一のもの）を使います。
- **データの読み込み**: ブラウザは最初に目次を読み込み、入力された NM_／NP_ 番号、遺伝子名、ゲノム位置に必要な束だけを取り寄せます。同じ NM_ 番号の全バージョンは同じ束に入っています。
- **UCSC に無いバージョン**: NCBI E-utilities（efetch）でその版の配列と CDS を取得します。UCSC にある同じ番号の版の mRNA 配列と照合し、その版の hg38 アライメントに重ねて位置を求めます。NP_ の場合は、NCBI のレコードからコードする NM_ を求めます。
- **参照配列**: 照合用の塩基は UCSC API から取得します（取得できない場合は Ensembl REST）。
- **hg19 → hg38**: Ensembl REST の assembly mapping を使います。
- **ミトコンドリアの遺伝子**: NCBI E-utilities で NC_012920.1 の GenBank レコードを取得し、遺伝子の範囲と正式な遺伝子名（MT-TL1 など）を読み取ります。UCSC の RefSeq データにはミトコンドリアの遺伝子が無いためです。外部データベースとの照合は対象外です。
- **外部データベースとの照合**（結果の表示後に非同期で実行）:
  - NCBI 順変換: `hgvs/{c.}/contextuals` で転写産物上の SPDI を求め、`spdi/{SPDI}/all_equivalent_contextual` で hg38（NC_）上の同じ変異を得ます。
  - NCBI 逆変換: hg38 の各塩基を SPDI にして `all_equivalent_contextual` で転写産物上の位置を得て、NCBI のレコードの CDS 範囲から c. 位置に直します。
  - Ensembl: VEP の `hgvs`（順変換）と `region`（逆変換、`hgvs=1`）を `refseq=1` で呼びます。
  - 欠失・重複・挿入は書き方（左寄せ・右寄せ、dup と ins）が違っても、hg38 の参照配列に適用した結果が同じなら一致とします。
  - NCBI はイントロン内の変異に対応していません。逆変換で返すのは現行版の NM_ だけです。Ensembl は現行版の NM_ しか持っておらず、応答に数十秒かかったり一時的なエラーを返したりします（自動で再試行します）。照合できない場合は理由つきで「確認不可」と表示します。
  - 画面では、先頭 5 件の結果を自動で照合します。それ以降は候補ごとの「照合する」から実行します。

座標計算は利用者のブラウザ内で行います。外部サービスへの問い合わせも、ブラウザから NCBI・Ensembl・UCSC へ直接送られ、本ツールのサーバーを経由しません。インターネット接続が必要なのは、転写産物データの読み込みのほか、参照塩基の照合、hg19 からの変換、UCSC に無いバージョンの配列取得、ミトコンドリアの遺伝子情報、外部データベースとの照合だけです。接続できない場合も位置は計算されますが、照合は行われません。UCSC に無いバージョンは、NCBI に接続できないと別の版で計算し、その旨を表示します。

## 正しさの検証

### 1. ClinVar を正解とした大規模検証（`npm run validate`）

ClinVar の `variant_summary.txt.gz`（GRCh38）から、NM_ の c. 表記と hg38 の位置がそろった変異を 9,000 件抽出しました。変異の種類ごとに層化抽出しています（エクソン内の置換 3,000、イントロン 1,500、5'UTR 500、3'UTR 500、欠失 1,500、重複 1,000、挿入 500、欠失挿入 500）。このサンプルで、本ツールと同じ関数の結果を照合します。

| 検証項目 | 内容 |
| --- | --- |
| 形式2 | `NM_:c.` から求めた hg38 位置が ClinVar と一致するか。置換は塩基の鎖の向きも確認します。欠失・挿入は、hg38 の参照配列に両方の変異を適用し、変異後の配列が同一かで判定します |
| 形式1（逆変換） | ClinVar の hg38 位置から求めた c. 位置が ClinVar の表記と一致するか |
| 形式3 | ミスセンス・ナンセンス変異の `NP_:p.` から求めたコドン範囲に正解位置が含まれるか。一部（300 件）は参照アミノ酸と 1 塩基置換の結果も照合します |
| 形式4 | `遺伝子名:c.` の候補に正解位置が含まれるか |
| 画面と同じ処理 | 300 件を画面と同じ処理全体（リファレンス照合を含む）で確認します |

サンプルは 2 つあります。1 つ目（開発用）は、見つかった不具合の修正に使いました。2 つ目（評価用）は、開発用に含まれた 3,919 遺伝子をすべて除外して抽出した、**一度も見ていない遺伝子だけ**のサンプルです。

| サンプル | 一致 / 照合件数 | 一致率 |
| --- | ---: | ---: |
| 開発用（[`report.md`](validation/report.md)） | 22,894 / 22,900 | 99.97% |
| 評価用・未見の遺伝子（[`report-heldout.md`](validation/report-heldout.md)） | 23,214 / 23,226 | 99.95% |

不一致 18 件はすべて原因を調べました。本ツールが警告なしに誤った位置を出したケースはありませんでした。大半は、hg38 の参照配列の欠損（SHANK3、MROH8）か ClinVar 側の表記誤りです。いずれも NCBI の転写産物配列と直接比べて確認しました。検証で見つかった不具合 4 件は修正済みで、回帰テストに含めています。詳しくは [`validation/ANALYSIS.md`](validation/ANALYSIS.md) を参照してください。

旧バージョンの NM 番号だけを集めた 3 つ目のサンプル（4,827 件、[`report-historical.md`](validation/report-historical.md)）でも検証しました。

- 本ツールのデータにある旧版では、3,689 / 3,781 件（97.57%）が一致しました。不一致 92 件に座標計算の誤りはありませんでした。79 件は GAGE・GSTT2 など、ほぼ同じ配列のコピーを持つ遺伝子で、UCSC が NCBI とは別のコピーに対応付けています。現在はこの 79 件すべてに分節重複の注意が出ます。
- データに無い版は、NCBI の配列で照合して 659 / 703 件（93.7%）が一致しました。以前の方法（別の版で代わりに計算）では 514 / 704 件（73.0%）でした。残りは、計算を断るエラー（37 件）、注意付きの結果（6 件）、ClinVar の誤り（1 件）です。**注意なしに誤った位置を出したケースはありませんでした。**

公開版（必要なデータだけを読み込む方式）でも、開発用サンプルの 9,000 件を検証しました（[`report-browser.md`](validation/report-browser.md)）。入力 1 件ごとにデータを空の状態に戻し（ページを開き直したのと同じ状態）、形式 1〜4 をすべて画面と同じ処理で換算しています。一致は 22,522 / 22,528 件（99.97%）で、不一致 6 件は上の開発用サンプルと同じ SHANK3 の 6 件です。新しい読み込み方式による不一致はありませんでした。この検証では、ゲノム位置から入力したときの候補一覧に ClinVar の NM_ が出るかも確かめています。ClinVar が旧版の NM_ で記録し、その位置が現行版の転写産物の範囲外にある 67 件は、現行版だけを表示する仕様のため「対象外」としました。

外部データベースとの照合そのものも検証しました（[`report-external.md`](validation/report-external.md)）。旧版サンプルから 536 件を選んで照合したところ、NCBI が本ツールの正しい結果を「不一致」とした誤警報は 1 件だけでした（ORAI1、もともと注意が出るケース）。一方、配列が同一の重複コピー（GSTT2 など）の取り違えは、NCBI も同じコピーを選ぶため外部照合では検出できません。旧版やイントロン内の変異は「確認不可」になりやすいです。詳しくは [`validation/ANALYSIS.md`](validation/ANALYSIS.md) を参照してください。

`validate-clinvar.ts` と `validate-browser.ts` は、外部サービスへの問い合わせを各サービスの公表している上限より少なく抑えます（UCSC 1 秒に 1 回、Ensembl 1 秒に 4 回、NCBI 1 秒に 2.5 回）。院内など回線を共有する場所から実行しても、接続元が締め出されないようにするためです。取得した参照配列は `validation/.cache/` に保存し、次回以降は問い合わせずに使います。

### 2. 回帰テスト（`npm test`）

`tests/` に 149 件のテストがあります。

- `parse.test.ts`: 色々な書き方の入力（全角文字、ClinVar 形式、1 文字・3 文字のアミノ酸記号、ミトコンドリアの m. 表記、エラー入力）の解析
- `mapping.test.ts`: ClinVar の正解値を使った座標計算（両方の鎖、イントロン、UTR、欠失・挿入、遠い上流、修正した不具合の再発防止）
- `seqalign.test.ts`: バージョン間の配列照合（延長、置換、欠失、ゲノムのアライメントとの合成）
- `convert.test.ts`: 画面と同じ処理全体（必要な束だけを読み込む方式で実行。リファレンス照合、注意表示、複数コピーの遺伝子、UCSC に無いバージョン、バージョン番号なしの全版比較、候補の並び順、hg19 からの変換、ミトコンドリア DNA、エラー表示）
- `verify.test.ts`: NCBI・Ensembl との照合（一致、位置をずらすと不一致になること、重複コピーの検出、イントロン、dup と ins の等価判定、Ensembl に無い旧版）

外部 API の応答は `tests/fixtures/remote.json` と `tests/fixtures/external.json` に保存したものを再生します。そのため、テストはオフラインでも同じ結果になります。テストケースを追加したときは、`RECORD_FIXTURES=1 npm test` で応答を記録し直してください。

## 注意

変換結果は参考情報です。依頼書に記入する前に、ゲノムブラウザで目的の変異であることを必ず確認してください。
古くから知られる変異は、シグナル配列を除いた成熟型タンパク質の番号で表記されていることがあります。その場合は、シグナル配列を含む番号に直してから入力してください。

### 対象にならない変異

本ツールが扱うのは、位置を指定して調べる小さな変異です（かずさ遺伝子検査室のがん関連遺伝子のシングルサイト解析では 10 塩基以内の欠失・挿入）。難病の家系解析では、次の変異は位置を指定するシングルサイト検査の対象外か、別の方法が必要になることが多いので、検査会社に相談してください。

- エクソン単位以上の欠失・重複（CNV）。MLPA 法などで調べます。
- 反復配列の伸長（ハンチントン病、筋強直性ジストロフィー、脆弱 X 症候群などのリピート病）
- 偽遺伝子や相同領域がある遺伝子（CYP21A2、SMN1/SMN2、GBA1、PKD1、PMS2 など）。本ツールは重複領域の注意を出しますが、受け入れの可否は検査会社が判断します。
- ミトコンドリア DNA の変異は、変異の有無だけでなく割合（ヘテロプラスミー率）が問題になることがあります。割合の測定ができるかを確認してください。
